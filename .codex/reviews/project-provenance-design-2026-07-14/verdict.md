# 结论

`REVISE`，L2 评分 `78 / 100`。`Project Provenance Store` 的目标和任务中心模型成立，也与当前 S4 的不可变候选、最终内容快照、项目外凭证、审计锚、正式引用 CAS 和安全恢复目标一致；但附件不能原样升级为正式技术真源。

不需要把整套方案退回 P1、P2 或重新会签 007、008、009、S3。推荐将其收敛为 S4 技术架构中的“项目变更溯源与安全回退”边界能力，复用现有 Task Registry、控制身份和五类独立结论链。第一版范围移交 P3，具体回退任务编排移交 P4。

# 为什么

1. 既有真源已经承诺交付物可追溯、Agent 跑偏回退节点、候选与最终快照身份、项目外凭证、审计锚和 CAS；附件主要是这些 S4 必答项的数据模型细化，不是新的前置产品路线。
2. 附件新增的 `Attempt Record`、文件 blob/patch 摘要、集成采纳关系、派生索引和追加式回退记录有价值，但必须并入现有对象模型，不能形成第二套任务、验证或正式提升真源。
3. 附件同时混入 S4 架构、P3 版本裁剪和 P4 执行流程。若整份冻结，会违反当前阶段“不冻结版本路线、不生成具体执行任务包”的边界。
4. 若把 Agent/文件级溯源升级为用户可感知产品能力，或要保存完整宿主对话、改变回退确认边界，才需要先建立 Change Request 并追补相应产品/交互真源；作为现有门禁的内部审计机制则无需追补前阶段。

# 必须修改

1. 保留现有五类独立结论：候选验证、产品与交互评估、独立审查、精确最终集成复验、正式提升。不能压缩成单一 `Verification -> Integration -> Formal Commit`。
2. 消除 Git 自引用：位于提交内的记录不得保存该提交自身 OID。项目内记录使用预生成 `integration_id` 并绑定最终内容快照；CAS 后的正式 OID 放入项目外不可变提升回执或受保护的追加式索引。
3. 将 Agent 字段拆为“声明身份、宿主绑定身份、已验证身份”。`host_task_id` 等自报字段只能用于关联，不能被表述为可信身份；可信级别必须绑定宿主凭证、控制身份、任务包摘要、基线和产物摘要。
4. 基线必须覆盖实际输入。默认从干净隔离 worktree 的不可变提交启动；如允许脏工作区，先物化完整授权输入快照，覆盖 staged、unstaged、未跟踪、删除、mode、symlink 和 submodule 等状态。
5. `partially-accepted` 不能只记录文件名。部分采纳必须物化为新的集成候选/最终内容快照，记录精确 before/after blob、采纳 delta 和 `derived_from`，并重新独立复验。
6. “文件后来未修改”只能说明文本重叠较少，不能证明安全回退。回退必须基于精确已采纳 delta，在当前正式基线上三方 dry-run，检查路径变化、跨文件/API/schema/config 依赖和用户未提交改动；结果只能是回退候选，验证通过后才能正式提升。
7. `.codex/provenance/` 若采用，必须在最终内容快照形成前写入；不得扩大复验后的审计锚白名单，也不得在 CAS 提升后补写项目内容。`index.json` 只作可重建派生索引，不参与正确性裁决。
8. 删除“项目外保存宿主任务完整对话”的默认要求。默认只保存最小结构化凭证和必要证据摘要；若确需保存完整对话，必须先通过 Change Request 明确保留期、访问权、删除权、脱敏和用户确认。
9. 把“第一版四项范围”标记为 P3 输入候选，把 revert/补偿任务的具体状态与编排留给 P4；S4 只冻结不变量、对象关系、状态边界、适配器接口、失败标准和验证方案。
