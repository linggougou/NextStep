# 项目上下文摘要（P2.2 产品载体与交互形态裁决）

生成时间：2026-07-09 01:41:12 CST

## 1. 现问题

- 已会签的 `P2 产品原型` 与 `P2 UI 设计真源输入要求` 默认把 `项目驾驶舱 + 先做 UI` 当成事实。
- 已建立的 `S3 UI 设计真源` 与活动计划进一步把这条 `UI-first` 路径包装成了当前正式主路线。
- 用户明确指出：在 `Web / App / Skill / MCP / 无 UI` 都未裁决前，直接进入 UI 设计顺序不成立。

## 2. 本轮裁决目标

- 暂停当前 `S3 UI 设计真源` 主路线。
- 插入 `P2.2 产品载体与交互形态裁决`。
- 判断什么是 NextStep 的主载体、辅助入口和后续集成面。
- 明确在什么条件下可以不进入 UI 分支。
- 将现有 `P2` / `S3` 材料统一降级为 `UI-first` 候选分支输入或草案。

## 3. 关键影响面

- `PROJECT_ROUTE_LOCK.md`：当前阶段回调到 `S2.5 / P2.2`，`S3` 改为待载体裁决。
- `docs/product-specs/002-005`：上游蓝图、旅程、能力地图、文档契约都必须改成“先裁决载体，再按分支进入 UI 或非 UI 真源”。
- `docs/design-docs/p2-*`：保留已会签事实，但明确只是 `UI-first` 候选分支输入。
- `docs/design-docs/s3-ui-design-source.md` 与 `docs/exec-plans/active/s3-ui-design-source.md`：降级为暂停中的候选分支草案。
- `.codex/`：新增路线纠偏留痕与验证结论。

## 4. 当前建议结论

- 主载体建议：`Web 项目驾驶舱`
- 辅助入口建议：`聊天 / Skill`
- 后续集成面建议：`MCP 服务 / API`
- 当前不作为主路线：`纯 App`、`纯 MCP`、`纯无 UI`

说明：以上仍属于建议结论，必须通过 `docs/product-specs/006-product-carrier-decision.md` 会签后才算当前真源。

- 不会签 `S3 UI 设计真源`
- 不进入 `S4 技术架构`
- 不拆版本路线、大里程碑、小里程碑
- 不写代码
- 不冻结技术栈
