## 4. 必填字段

| 字段 | 内容要求 | 合格标准 |
|---|---|---|
| 主入口 | 说明用户在哪个 Agent、聊天环境或宿主工具中调用 Skill，并固定主对话 Agent 为唯一用户沟通与决策入口 | 用户能明确从哪里开始使用，执行 Agent 和集成 Agent 不会绕过主对话联系用户 |
| 触发方式 | 说明显式调用、系统建议调用和禁止静默执行规则 | 自动建议与正式执行边界清楚 |
| 三层职责 | 区分主对话 Agent、集成 Agent、执行 Agent 的逻辑职责，并说明物理上采用主对话扁平调度独立任务 | 主对话只沟通、决策和调度且不读写项目；集成负责准备与集成但不能自我批准；执行只完成单一任务包 |
| 上下文防火墙 | 说明独立任务只接收最小任务包，项目事实经正式真源、任务注册表和最小检查点传递 | 完整聊天、日志、代码差异、测试输出和内部推理不会回灌主对话，也不会复制给无关任务 |
| 计划内分派与例外边界 | 说明用户确认计划后哪些任务可自动分派，以及哪些情况必须暂停并请求用户决定 | 普通排队、开始和完成不反复打断用户；路线、范围、不可逆动作、安全、显著成本或验收失败必须上报 |
| 主对话最小摘要 | 说明默认安静、按需展开的状态与阶段摘要范围 | 默认只呈现当前阶段、结果、数量、阻塞、关键风险、待决策项和下一决策点 |
| 恢复边界 | 说明主对话如何从项目真源、最小检查点和结构化恢复结果重建状态 | 不默认加载完整旧聊天，不允许主对话为恢复而直接读取项目文件 |
| 项目根解析 | 定义项目标识如何解析到唯一项目根和真源目录 | 同名、缺失、越界和无权限情况均有处理规则 |
| 当前阶段识别 | 说明如何读取路线锁、阶段真源和验证留痕 | 不依赖聊天上下文猜测阶段 |
| 主流程 | 说明输入、建议、确认、写入、验证和状态更新顺序 | 正式写入前后边界可复现 |
| 真源回写映射 | 说明每类确认写入哪份真源 | 不把聊天记录直接视为正式真源 |
| 写入一致性 | 定义候选变更、确认、写入、验证、提交状态和失败回滚 | 写入失败不得误报生效 |
| AI 自动建议边界 | 说明 AI 可以自动整理、建议和检查什么 | 不偷渡正式确认 |
| 用户确认节点 | 说明哪些动作必须由用户显式确认 | 至少覆盖冻结、会签、路线、变更和门禁结论 |
| 多项目切换 | 说明切换、同名项目和跨项目只读比较规则 | 不覆盖其他项目真源 |
| 阻塞与异常 | 覆盖缺真源、无权限、版本冲突、部分写入和验证失败 | 每类异常有恢复或回退入口 |
| 候选分支处理 | 说明 Web / UI 候选材料的保留和恢复条件 | 不误当当前主路线 |
| 验收矩阵 | 每项包含证据、通过条件和失败条件 | 可逐项判断通过、退回、需讨论或阻塞 |
| 变更入口 | 说明会签后如何修改本文和 S3 真源 | 必须进入 Change Request |
| 不可偏离项 | 明确 Skill、聊天和文档真源的职责边界 | 与载体裁决和路线锁一致 |

## 6. 会签标准

用户会签本文时，需要确认：

- 本文没有覆盖 005 的历史会签事实。
- Skill 分支必填字段足以支撑 S3 的可执行、可验证和可回滚边界。
- 主对话 Agent 作为唯一用户入口，只承担沟通、决策和扁平调度，不读取或修改项目文件；开发、文档、测试、评估、审查、验证和集成由隔离任务完成。
- 计划内自动分派、默认安静和按需展开足以保护主对话的语义稳定性与用户心流；减少 Token 不是本文的产品目标或验收项。
- 普通执行消息不会进入主对话，只有阻塞、验收失败或需要用户决定的例外才会上报。
- 项目根解析和写入一致性要求足以防止写错项目或误报生效。
- 本文可以与 005 一起作为 S3 Skill 交互真源的格式依据。
