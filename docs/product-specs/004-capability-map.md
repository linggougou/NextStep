# NextStep 能力地图

状态：P1 草案，待用户会签  
记录日期：2026-07-07  
上游真源：`docs/product-specs/002-complete-project-blueprint.md`

## 1. 能力分层

NextStep 的能力按 4 层组织。

| 层级 | 作用 | 包含能力 |
|---|---|---|
| 项目真源层 | 冻结项目事实 | 需求入口、项目成型、真源管理 |
| 规划闭环层 | 把项目拆成可交付路径 | 版本规划、模块拆解、阶段门禁 |
| 执行控制层 | 让 Agent 按边界做事 | 执行任务包、结果验收、失败回退 |
| 交付治理层 | 维护长期项目状态 | 变更分流、交付归档、风险管理 |

## 2. 能力清单

### 2.1 需求入口

目的：接住用户的模糊表达，识别表层需求和深层问题。

输入：

- 用户自然语言描述。
- 可选背景材料。

输出：

- 原始需求记录。
- 意图理解摘要。
- 关键缺口。
- 下一步澄清建议。

硬性指标：

- 必须识别目标、场景、约束、输出和非目标缺口。
- 不能直接生成开发任务。

### 2.2 项目成型

目的：把入口需求整合成完整项目。

输入：

- 原始需求记录。
- 用户补充信息。

输出：

- 项目总 Spec。
- 项目目标。
- 目标用户。
- 核心场景。
- 项目范围。
- 非目标。
- 成功指标。

硬性指标：

- 项目真源不完整时，不允许进入版本规划。
- 用户必须确认当前项目定义。

### 2.3 真源管理

目的：维护项目事实，避免聊天记录替代项目真源。

输入：

- 已确认决策。
- 阶段产物。
- 验收结论。

输出：

- 当前项目真源。
- 决策历史。
- 阶段状态。
- 变更记录。

硬性指标：

- 一个事实只能有一个当前真源。
- 任何执行任务必须引用当前真源。

### 2.4 版本规划

目的：把完整项目拆成多个可交付版本。

输入：

- 项目总 Spec。

输出：

- V1 范围。
- V2 范围。
- Backlog。
- 每个版本的交付物和验收标准。

硬性指标：

- V1 必须有独立交付价值。
- 后续版本不得污染当前版本。
- 每个版本必须有明确非目标。

### 2.5 模块拆解

目的：把版本拆成可量化、可执行、可验收的小闭环。

输入：

- 版本路线。

输出：

- 模块闭环清单。
- 模块依赖关系。
- 模块 DoD。
- 模块验收方式。

硬性指标：

- 模块按业务闭环拆，不按纯技术层拆。
- 每个模块必须有输入、输出、DoD、非目标和失败处理入口。

### 2.6 阶段门禁

目的：阻止项目在未达标时进入下一阶段。

输入：

- 当前阶段状态。
- 当前阶段交付物。
- 验收标准。

输出：

- 通过。
- 退回。
- 需讨论。
- 阻塞。

硬性指标：

- 未通过不得进入下一阶段。
- 门禁结论必须可追溯。

### 2.7 执行任务包

目的：让执行 Agent 明确知道当前只做什么。

输入：

- 当前模块闭环。
- 当前项目真源。
- 当前版本边界。

输出：

- 执行背景。
- 任务目标。
- 输入材料。
- 输出格式。
- 非目标。
- 验收标准。
- 失败处理规则。

硬性指标：

- 没有模块闭环不得生成执行任务包。
- 执行任务包不能改变项目真源。

### 2.8 结果验收

目的：判断 Agent 或用户产出是否符合当前闭环。

输入：

- 执行结果。
- 模块 DoD。
- 验收标准。

输出：

- 验收报告。
- 问题清单。
- 修复入口。
- 阶段门禁结论。

硬性指标：

- 验收结论只能是通过、退回、延期、变更、阻塞。
- 未验证不得包装为完成。

### 2.9 变更分流

目的：防止新需求偷渡进当前闭环。

输入：

- 新需求。
- 漏项。
- 执行中发现的问题。

输出：

- 当前阶段缺口。
- 当前阶段增强项。
- 后续版本需求。
- Backlog。
- 拒绝。
- 高风险路线变更。

硬性指标：

- 影响路线、版本边界或验收门禁的变更必须用户确认。
- 变更结论必须写入真源。

### 2.10 交付归档

目的：让项目成果、证据和风险可追溯。

输入：

- 已通过验收的交付物。
- 阶段报告。
- 风险和延期项。

输出：

- 交付清单。
- 归档记录。
- 后续版本入口。

硬性指标：

- 交付前必须有验收结论。
- 交付后新增需求必须进入后续版本或变更管理。

## 3. 能力优先级

| 优先级 | 能力 | 原因 |
|---|---|---|
| P0 | 项目成型、真源管理、版本规划、模块拆解、阶段门禁 | 决定 NextStep 是否能防止项目漂移 |
| P1 | 执行任务包、结果验收、变更分流 | 决定项目是否能持续落地 |
| P2 | 交付归档、风险管理、外部 Agent 连接 | 决定长期项目是否可维护 |
| P3 | 多人协作、Agent 市场、知识库扩展 | 属于后续扩展，不进入当前核心闭环 |

## 4. 能力边界

NextStep 可以生成执行任务包，但不等同于执行 Agent。

NextStep 可以管理项目状态，但不等同于传统项目管理软件。

NextStep 可以使用 AI 分析需求，但不等同于聊天助手。

NextStep 可以输出提示词，但提示词只是执行任务包的一部分。

## 5. P2 输入

本能力地图通过后，P2 需要把能力拆成版本路线和模块闭环。

P2 至少需要输出：

- V1/V2/V3/Backlog 路线。
- V1 模块闭环清单。
- 每个模块的输入、输出、DoD、验收方式。
- 验收矩阵。
- 模块依赖关系。
