## 3. 下游验收层次

| 验收层次 | 适用范围 | 核心依据 | 通过条件 |
|---|---|---|---|
| 集成验收 | 所有路线 | 技术方案、里程碑 DoD、测试证据 | 目标能力可集成且回归验证通过 |
| 交互验收 | 所有路线 | 当前分支已会签交互真源 | 实际入口、流程、确认边界、异常和回写行为符合交互真源 |
| 产品验收 | 所有路线 | PRD、产品定义、产品载体裁决 | 用户目标、范围、非目标和成功条件符合产品真源 |
| UI 还原验收 | 仅含 UI 分支 | 已会签 UI 设计真源及其证据 | 页面、组件、状态和响应式还原满足 UI 契约 |

验收顺序不得把 UI 还原验收设为所有路线的必经门禁，也不得用 UI 还原验收替代交互验收或产品验收。

## 4. 对 P3 契约的补充

005 第 5.2 节中的 `大里程碑验收标准` 在当前路线下解释为：

> 能判断大里程碑是否可进入交互验收和产品验收；只有该大里程碑属于含 UI 分支时，才追加判断是否可进入 UI 还原验收。

P3 的验收矩阵必须为每个大里程碑明确：

- 对应的已会签交互真源。
- 交互验收项、证据、通过条件和失败条件。
- 产品验收项、证据、通过条件和失败条件。
- 是否属于含 UI 分支；若是，追加 UI 设计真源和 UI 还原验收项。
- 任一必需验收失败后的退回节点和变更入口。

## 5. 对验收报告契约的补充

005 第 6 节的验收报告字段继续有效，并补充以下要求：

| 字段 | 补充要求 | 合格标准 |
|---|---|---|
| 验收类型 | 标记集成、交互、产品或 UI 还原验收 | 不把不同验收目的混为一个模糊结论 |
| 对应真源 | 交互验收引用当前分支交互真源；产品验收引用产品真源；UI 验收仅引用已会签 UI 设计真源 | 验收依据与验收类型匹配 |
| 分支适用性 | 明确当前交付是否属于含 UI 分支 | 非 UI 路线不得因缺少 UI 报告被判失败 |
| 证据 | 每项证据能对应到验收项和真源条款 | 结论可复核，不依赖“看起来可以” |
| 结论 | 只能是通过、退回、需讨论、阻塞之一 | 任一必需验收未通过时不得进入交付 |

不同验收类型可以形成独立报告，也可以在同一报告中分区记录，但必须分别给出证据和结论。

### 5.1 编排产物的独立结论链

当交付由主对话 Agent 扁平分派的隔离任务产生时，以下五类结论必须分别记录，不能合并为一个模糊的“已完成”：

| 独立结论 | 判断对象 | 通过条件 | 不得替代者 |
|---|---|---|---|
| 候选验证 | 执行 Agent 物化的不可变候选提交或等价快照 | 任务要求的测试与验证通过，结论绑定候选摘要和控制身份 | 不能替代产品/交互评估或最终集成复验 |
| 产品与交互评估 | 同一不可变候选及其适用产品、交互真源 | 产品范围、用户目标、交互流程和确认边界分别符合对应真源 | 不能用候选验证或 UI 还原验收代替 |
| 独立审查 | 高风险任务、阶段出口或发布判断的候选与证据 | 独立审查 Agent 给出可追溯结论，无未裁决的阻塞问题 | 集成 Agent 的自查不能替代 |
| 精确最终集成复验 | 集成 Agent 生成的不可变最终内容快照 | 独立最终复验绑定精确内容摘要、预期正式基线、控制代际、任务尝试和验证任务身份 | 候选阶段的旧结论不能替代 |
| 正式提升 | 经复验的最终内容快照及其审计锚 | 项目外不可变复验凭证与项目根审计锚一致，正式引用以 CAS、快进或等价原子引用移动成功 | “准备提升”或集成 Agent 声称成功不能替代 |

每类结论只能是 `通过`、`退回`、`需讨论` 或 `阻塞`。集成 Agent 可以执行诊断性检查，但不得批准自身生成的候选、最终内容快照或审计锚；最终复验与审计锚范围校验必须由独立角色完成。

候选摘要、最终内容摘要、预期正式基线、控制代际、任务尝试、任务包摘要或派发消息身份任一变化，所有绑定旧身份的结论立即失效。集成冲突、重放、补写非审计白名单内容或 CAS 前基线变化都必须生成新的不可变最终内容快照并重新复验，不得沿用旧通过结论。

正式提升前，最终内容快照必须已包含全部业务与产品真源、会签或阶段状态、任务注册表、检查点和复验前验证留痕。独立复验后只允许追加经独立白名单校验的项目根 `.codex` 审计锚；项目外凭证不能替代项目根留痕，审计锚也不能修改产品真源或受门禁状态。CAS 失败时保持 `待正式提升`，不得发送成功摘要或归档为成功。

## 6. 禁止事项

- 不得无条件要求所有路线提供 UI 验收报告。
- 不得把聊天记录或未会签草案作为交互验收真源。
- 不得用产品验收通过掩盖交互验收失败。
- 不得用交互验收通过掩盖产品范围偏离。
- 含 UI 分支不得跳过 UI 还原验收。
- 不得在未实际验证时写入通过结论。
- 不得由集成 Agent 自我批准其集成结果，或用候选阶段结论代替精确最终集成复验。
- 不得在最终内容或正式基线变化后沿用旧复验凭证、审计锚证明或正式提升结论。

## 7. 会签标准

用户会签本文时，需要确认：

- 当前主路线固定执行交互验收和产品验收。
- UI 还原验收只在含 UI 分支时追加。
- 本文足以消除 005 中 `UI / 产品验收` 对非 UI 路线的默认绑定。
- P3 验收矩阵和后续验收报告能够据此区分验收类型与分支适用性。
- 候选验证、产品与交互评估、独立审查、精确最终集成复验和正式提升形成五类可独立判定的门禁，集成 Agent 不能自我批准。
- 最终内容变化使旧结论失效，项目外复验凭证、项目根审计锚和正式引用 CAS 共同约束正式提升。
