# NextStep 用户旅程

状态：P1 草案，待用户会签  
记录日期：2026-07-07  
上游真源：`docs/product-specs/002-complete-project-blueprint.md`

## 1. 核心旅程

NextStep 的核心旅程是：

```text
我有一个想法
↓
系统帮我理解和补全需求
↓
系统记录并冻结需求真源
↓
系统从产品经理视角输出产品定义
↓
系统输出产品原型并让我会签
↓
系统基于原型形成 UI 设计真源
↓
系统完成技术选型与架构
↓
系统拆出版本路线和大里程碑
↓
系统把大里程碑拆成小里程碑
↓
系统生成执行任务包
↓
Agent 或用户执行小里程碑
↓
系统测试验收并合入大里程碑
↓
系统做 UI 还原验收和产品定义验收
↓
项目交付归档
```

变更管理贯穿整个旅程。用户新增需求、发现漏项、修改设计、调整技术方案或验收失败时，NextStep 必须先分流变更，再决定是否更新当前真源。

## 2. 角色

### 2.1 用户

用户负责提供目标、业务背景、取舍判断和最终确认。

用户不需要一开始就会写 PRD、Prompt、技术方案或测试标准。

### 2.2 NextStep

NextStep 负责把用户的表达整合成项目结构，持续维护项目状态，并在关键节点阻止项目漂移。

### 2.3 执行 Agent

执行 Agent 负责按任务包完成具体产出。它不能自行扩大范围，也不能绕过验收门禁。

## 3. 旅程阶段

| 阶段 | 用户状态 | NextStep 动作 | 输出物 | 硬性完成条件 |
|---|---|---|---|---|
| 1. 需求入口 | 只有模糊想法 | 提取目标、场景、约束、缺口 | 原始需求记录 | 用户确认需求被正确理解 |
| 2. 需求补全与冻结 | 需求还不完整 | 追问、补全、记录、冻结需求 | 需求清单 | 用户确认当前需求真源 |
| 3. 产品定义 | 不知道产品完整长什么样 | 从产品经理视角整合产品目标、范围、非目标和验收 | PRD / 产品定义 | 产品范围可验收 |
| 4. 产品原型 | 不知道页面和流程是否对 | 输出原型和关键交互 | 原型会签记录 | 用户确认原型 |
| 5. UI 设计 | 不知道最终视觉标准 | 基于原型输出设计真源 | UI 效果图和设计规范 | UI 验收标准明确 |
| 6. 技术选型 | 不知道怎么实现 | 输出技术栈、架构、风险和回滚方案 | 技术方案 | 技术路线可验证 |
| 7. 版本与大里程碑 | 不知道整体推进节奏 | 拆版本和大里程碑 | 版本路线图、大里程碑计划 | 每个大里程碑可集成验收 |
| 8. 小里程碑拆解 | 大里程碑仍然太大 | 拆可量化小里程碑 | 小里程碑清单 | 每个小里程碑有输入、输出、DoD |
| 9. 执行准备 | 不知道怎么让 Agent 做 | 生成执行任务包 | 执行任务包 | 任务包绑定范围和验收 |
| 10. 小里程碑执行 | Agent 开始产出 | 维护当前小里程碑状态 | 过程记录 | 不允许偷渡新需求 |
| 11. 小里程碑验收 | 不知道能否合入 | 测试和验收当前小里程碑 | 小里程碑验收报告 | 测试通过后才能合入 |
| 12. 大里程碑验收 | 一组能力完成 | 集成验收、UI 还原验收、产品定义验收 | 大里程碑验收报告 | 三类验收均通过 |
| 13. 变更分流 | 发现新需求或漏项 | 分类进入当前缺口、后续版本、Backlog 或拒绝 | Change Request | 不污染当前闭环 |
| 14. 交付归档 | 准备完成阶段 | 固化交付物和风险 | 交付清单 | 证据可追溯 |

## 4. 关键使用场景

### 4.1 用户只有一句想法

输入：

```text
我想做一个 AI 项目推进工具。
```

NextStep 输出：

- 原始意图。
- 深层问题。
- 目标用户假设。
- 核心场景假设。
- 待确认问题。
- 推荐的项目定义。
- 是否允许进入需求冻结与产品定义。

### 4.2 用户想直接让 Agent 开发

NextStep 应阻止直接开发，并提示当前缺少：

- 项目真源。
- 版本边界。
- 原型会签。
- UI 设计真源。
- 技术方案。
- 大里程碑和小里程碑闭环。
- 验收指标。

只有补齐后才能生成执行任务包。

### 4.3 用户中途提出新需求

输入：

```text
那顺便支持团队协作吧。
```

NextStep 输出：

- 新需求类型。
- 是否影响当前阶段 DoD。
- 影响范围。
- 建议分流结论。
- 是否需要用户确认更新路线锁。

### 4.4 Agent 结果跑偏

NextStep 不只是重新生成 Prompt，而是判断跑偏原因：

- 需求真源不完整。
- 版本边界错误。
- 模块拆解过大。
- 执行任务包不清晰。
- Agent 没遵守非目标。
- 验收指标不够硬。

然后把项目退回正确节点。

## 5. 用户感知目标

用户在使用 NextStep 时，应该始终能回答：

- 我现在在哪个阶段。
- 当前版本要交付什么。
- 当前模块要完成什么。
- 哪些东西明确不做。
- 当前结果是否通过。
- 下一步该做什么。
- 新想法应该放在哪里。

## 6. 旅程非目标

本阶段不定义具体 UI 页面，不定义技术实现，也不定义 Agent 调用协议。

这些内容应在后续 S2 原型与设计、S3 技术架构和 P3 执行机制设计中建立。
