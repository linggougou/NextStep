## 1. 阶段目标

基于已会签的 P2 产品原型、UI 设计真源输入要求和 P2.1 文档契约，产出可用于后续 UI 还原验收的 UI 设计真源。

## 4. Definition of Done

- UI 设计真源覆盖页面清单、页面目标、核心状态和关键交互。
- UI 设计真源覆盖组件状态表、响应式要求、空状态、错误状态和阻塞状态。
- UI 设计真源包含设计稿链接、截图证据和设计版本号。
- UI 验收清单明确，能够支撑后续 UI 还原验收。
- 不提前写入技术栈、API、数据库、版本路线、大里程碑、小里程碑或执行任务包。

## 5. 明确非目标

- 不做技术选型。
- 不写技术架构。
- 不拆版本路线。
- 不拆大里程碑或小里程碑。
- 不写代码。
- 不生成执行任务包。

## 6. 阶段出口

用户确认 UI 设计真源可作为后续 UI 还原验收依据后，才能进入 S4 技术架构或其他后续阶段。

## 7. 验证方式

- 文档存在性检查。
- 文档契约字段覆盖检查。
- 阶段偷跑关键词扫描。
- 占位文本和补丁残留检查。
- `git diff --check`。
