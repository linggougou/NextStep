## 1. 文档目标

本文保留一份在未来重新确认进入 `Web / UI` 路线时可恢复的 `S3 UI 设计真源` 草案。

当前它不是正式会签中的设计真源，也不构成当前阶段真源。

本文只回答：

- 核心页面应该如何组织信息。
- 每个页面需要覆盖哪些状态和关键交互。
- 关键组件在不同业务状态下如何表现。
- 桌面端、平板端和移动端如何保持项目状态优先。
- 后续 UI 还原验收应如何逐页面、逐组件核验。

## 4. 设计总原则

- 若未来恢复当前 `Web / UI` 候选分支，项目驾驶舱优先，聊天或 AI 建议只能是辅助入口。
- 用户必须在 5 秒内看懂当前在哪、下一步是什么、什么不能做。
- 所有推进动作都要显式绑定阶段门禁，不允许“看起来可以”的软通过。
- 交付物、风险、变更和阻塞必须被看见，不能藏进二级详情。
- 移动端可以减少信息密度，但不能退化成单一聊天流。

## 6. 页面共用布局规则

### 6.1 顶部区域

- 左侧固定显示项目名称、当前生命周期阶段和阶段状态。
- 中部显示当前页面标题与一句话目标。
- 右侧显示主行动、会签状态、设计版本号入口。

### 6.2 主内容区

- 第一屏必须出现当前状态、下一步和阻塞原因。
- 第二层展示交付物、风险、变更和证据链。
- 深层信息使用抽屉、折叠区或详情页，不允许默认铺满整屏。

### 6.3 辅助区

- AI 建议块只能放推荐判断、原因和待确认取舍。
- 不允许 AI 建议块占据主布局主列。
- 所有被锁动作都要同时展示“为什么不能做”和“先做什么”。

## 7. 页面详细设计

### 7.1 项目列表

- 页面目标：用户在进入系统后立即判断每个项目当前所处阶段、风险和是否可继续推进。
- 布局与信息层级：列表或卡片第一层展示项目名、定位、当前阶段、阶段状态；第二层展示缺失交付物、最近风险和下一步行动。
- 核心状态：进行中、阻塞、待会签、已交付、无项目。
- 关键交互：进入项目、创建项目、筛选状态、按风险排序、查看阻塞原因。
- 验收要点：不允许只有项目名称列表；必须能直接看出项目是否卡在当前阶段。

### 7.2 项目创建 / 需求入口

- 页面目标：帮助用户把模糊想法转成可补全的需求输入，而不是直接进入执行。
- 布局与信息层级：主区为输入区和 AI 理解区；侧区显示识别到的目标、场景、约束和缺口。
- 核心状态：空状态、已识别缺口、推荐补全、保存失败。
- 关键交互：粘贴想法、选择推荐补全项、确认 AI 理解、保存为需求记录。
- 验收要点：页面必须强调“先补全需求，再进入需求工作台”，不能出现直接开发入口。

### 7.3 需求工作台

- 页面目标：让需求补全、确认、冻结和退回修改具备明确轨道。
- 布局与信息层级：左侧为需求条目和缺口清单；右侧为确认记录、冻结状态和下一步入口。
- 核心状态：待确认、已确认、被拒绝、后置、已冻结。
- 关键交互：逐项确认、退回修改、标记后置、冻结需求、查看冻结后禁止动作。
- 验收要点：未冻结前必须阻止进入产品定义，并给出原因说明。

### 7.4 产品定义

- 页面目标：用结构化方式表达目标、用户、范围、非目标和成功指标。
- 布局与信息层级：顶部摘要显示产品定位；主体采用分区卡片呈现目标、目标用户、核心流程、范围与非目标、成功指标。
- 核心状态：草稿、待会签、已会签、退回修改。
- 关键交互：编辑结构化内容、查看上游来源、发起会签、查看退回意见。
- 验收要点：必须保持“产品经理视角”而非技术方案视角。

### 7.5 项目驾驶舱

- 页面目标：让用户每次进入项目都先看到当前阶段、当前缺口、下一步和风险。
- 布局与信息层级：首屏为当前阶段卡、下一步卡、交付物状态卡；第二屏为风险阻塞、变更提醒和近期会签记录。
- 核心状态：正常推进、待会签、阻塞、需讨论、无风险、存在变更。
- 关键交互：打开当前阶段真源、处理缺口、查看门禁结果、进入变更分流。
- 验收要点：驾驶舱首页不能被聊天区替代，聊天只能存在于辅助区域。

### 7.6 产品原型会签

- 页面目标：帮助用户确认页面清单、主流程、关键交互和不可偏离项。
- 布局与信息层级：顶部显示原型版本和会签状态；主体按页面清单、主流程、关键交互、不可偏离项分段。
- 核心状态：待会签、通过、退回、需讨论。
- 关键交互：查看原型摘要、标记疑问、提交会签结论、记录会签后果。
- 验收要点：若后续恢复该分支并进入会签，必须明确后续入口；退回时必须给出回到哪个文档修复。

### 7.7 阶段门禁

- 页面目标：把 DoD、当前缺口、结论和下一阶段入口固定成硬门禁。
- 布局与信息层级：左侧列出 DoD 项；右侧显示证据、结论、下一步入口和被锁动作。
- 核心状态：通过、退回、需讨论、阻塞。
- 关键交互：查看证据、打开对应真源、切换结论、查看阻塞原因、查看被锁动作说明。
- 验收要点：不得出现“基本通过”“差不多可进”之类软表述。

### 7.8 交付物中心

- 页面目标：让用户快速区分真源、草稿、待会签文档和证据文件。
- 布局与信息层级：按交付物类型分组展示；每条交付物显示状态、版本、更新时间、上游真源和验证入口。
- 核心状态：缺失、草稿、待会签、已会签、已归档。
- 关键交互：打开真源、查看证据、查看版本、发起变更、过滤状态。
- 验收要点：必须把“当前正式真源”与“辅助草稿”区分开。

### 7.9 变更分流

- 页面目标：把新需求、漏项和验收失败导向正确轨道，避免污染当前阶段闭环。
- 布局与信息层级：顶部显示当前影响判断；主体分当前阶段缺口、后续阶段、Backlog、拒绝四个分流结果区。
- 核心状态：当前缺口、增强项、后续阶段、Backlog、拒绝。
- 关键交互：发起变更、判断影响、记录分流结论、跳转到对应真源。
- 验收要点：不允许把新增需求直接塞回当前设计或当前实现。

## 9. 组件状态表

| 组件 | 状态 | 表现规则 | 验收要求 |
|---|---|---|---|
| 阶段状态卡 | 未开始 | 灰色边框，主标题不高亮 | 能一眼区分未开始与进行中 |
| 阶段状态卡 | 进行中 | 主标题高亮，显示当前缺口和下一步 | 必须同时显示缺口与推荐行动 |
| 阶段状态卡 | 待会签 | 显示待确认标签和会签入口 | 不得误导为已通过 |
| 阶段状态卡 | 门禁通过 | 显示通过结论和下一阶段入口 | 下一阶段入口必须明确 |
| 阶段状态卡 | 退回 | 红色告警样式，显示退回原因 | 必须能定位回修复入口 |
| 阶段状态卡 | 阻塞 | 深色阻塞样式，显示外部依赖或缺失条件 | 必须显示谁来解除阻塞 |
| 交付物卡片 | 缺失 | 空壳卡片，显示需要补齐什么 | 必须提供补齐入口 |
| 交付物卡片 | 草稿 | 显示草稿标识和最近更新时间 | 不得显示为正式真源 |
| 交付物卡片 | 待会签 | 显示待确认标识和证据入口 | 必须可追溯到当前版本 |
| 交付物卡片 | 已会签 | 显示通过标识、版本和会签日期 | 必须区分于草稿 |
| 交付物卡片 | 已归档 | 显示归档标识和替代真源入口 | 不得作为默认编辑入口 |
| 下一步行动 | 可执行 | 主按钮可点，附带原因说明 | 按钮文案必须是明确动作 |
| 下一步行动 | 被锁定 | 次级按钮或禁用态，显示锁定原因 | 必须说明先做什么 |
| 下一步行动 | 需用户确认 | 按钮旁显示确认提示 | 不得默认自动推进 |
| 下一步行动 | 需变更分流 | 按钮跳转到变更分流入口 | 不得直接写入当前真源 |
| 风险提示 | 信息 | 中性提示样式 | 不应抢主视觉 |
| 风险提示 | 警告 | 黄色提示样式，显示影响 | 必须说明建议动作 |
| 风险提示 | 阻塞 | 红色或深色阻塞样式 | 必须说明无法继续的原因 |
| 风险提示 | 路线变更 | 强提示样式，要求用户确认 | 必须链接到变更入口 |
| 会签按钮 | 待确认 | 主按钮可见，可进入确认流程 | 不得与保存按钮混淆 |
| 会签按钮 | 已确认 | 只读展示确认结果和时间 | 不得再次默认修改 |
| 会签按钮 | 退回修改 | 显示退回原因和修复入口 | 必须能回到对应真源 |
| 变更项 | 当前阶段缺口 | 标红并回链当前真源 | 必须计入当前缺口 |
| 变更项 | 增强项 | 标为可讨论，不阻塞当前闭环 | 不得默认插入当前范围 |
| 变更项 | 后续阶段 | 标记所属后续阶段 | 必须显示不是当前阶段工作 |
| 变更项 | Backlog | 标记后置 | 不得占用当前主操作位 |
| 变更项 | 拒绝 | 只读显示拒绝理由 | 必须保留审计痕迹 |
| AI 建议块 | 推荐 | 显示推荐动作和理由 | 不得取代用户确认 |
| AI 建议块 | 原因 | 显示证据来源或判断依据 | 理由必须可读 |
| AI 建议块 | 需要用户确认的取舍 | 显示明确选项 | 不得暗中默认其中一项 |

## 10. 响应式要求

| 终端 | 布局规则 | 必须保留 | 可以收起 |
|---|---|---|---|
| 桌面端 | 三列或双列布局，驾驶舱状态卡优先 | 当前阶段、下一步、交付物、风险、变更 | 深层说明、历史记录 |
| 平板端 | 双列布局，状态卡纵向堆叠 | 当前阶段、下一步、当前缺口、会签状态 | 详细证据说明、长表格 |
| 移动端 | 单列卡片流，但首屏必须先给阶段状态和下一步 | 当前阶段、状态、缺口、主行动、阻塞原因 | 扩展说明、二级证据、历史版本 |

响应式硬约束：

- 移动端不得退化成单一聊天流。
- 被锁动作在小屏上也必须保留，并展示锁定原因。
- 交付物状态和会签状态在所有断点上都必须可见。
- 驾驶舱首页在任意断点下都要把“当前阶段”和“下一步”放在首屏。

## 11. 空状态、错误状态与阻塞状态

### 11.1 空状态

| 场景 | 展示要求 | 下一步 |
|---|---|---|
| 无项目 | 显示项目创建入口和示例说明 | 创建项目 |
| 无交付物 | 显示缺失清单和当前阶段需要补齐的真源 | 补齐当前阶段交付物 |
| 无变更 | 显示“当前无待处理变更” | 继续当前阶段工作 |

### 11.2 错误状态

| 场景 | 展示要求 | 恢复方式 |
|---|---|---|
| 加载失败 | 展示错误描述、重试按钮和回退入口 | 重新加载或返回上一级 |
| 保存失败 | 保留用户输入，显示失败原因 | 重试保存 |
| 权限不足 | 显示当前无法操作的原因 | 联系管理员或切换可读模式 |

### 11.3 阻塞状态

| 场景 | 展示要求 | 禁止行为 |
|---|---|---|
| 门禁未通过 | 显示未通过项、证据缺口和修复入口 | 不允许进入下一阶段 |
| 缺少真源 | 明确缺哪份真源、为什么需要 | 不允许跳过补齐 |
| 需用户确认 | 显示待确认事项和影响范围 | 不允许 AI 自动替用户决定 |

阻塞状态固定文案模板：

```text
当前还不能继续。
原因：当前阶段门禁未满足。
先做什么：补齐缺失真源或完成用户确认。
```

## 12. 关键文案和语气规范

- 使用“当前阶段”“下一步”“阻塞原因”“会签结论”这类直接词汇，不使用含糊表达。
- 优先写动作导向文案，如“补齐需求缺口”“发起会签”“查看当前 DoD”。
- 禁止使用“先凑合”“先做 MVP”“差不多可以”之类弱化门禁的文案。
- 当动作被锁定时，必须同时给出原因和前置动作。

## 13. UI 验收清单

### 13.1 页面级验收

- 项目列表能直接展示项目阶段、状态、缺口和下一步。
- 项目创建 / 需求入口能展示 AI 已识别缺口和推荐补全，不出现直接开发入口。
- 需求工作台能展示确认、退回、后置和冻结轨道。
- 产品定义能结构化展示目标、用户、范围、非目标和成功指标。
- 项目驾驶舱首屏能展示当前阶段、下一步、交付物和风险。
- 产品原型会签能展示会签状态、会签结论和会签后果。
- 阶段门禁只能给出通过、退回、需讨论、阻塞四类结论。
- 交付物中心能区分缺失、草稿、待会签、已会签和已归档。
- 变更分流能区分当前缺口、后续阶段、Backlog 和拒绝。

### 13.2 组件级验收

- 阶段状态卡覆盖未开始、进行中、待会签、门禁通过、退回、阻塞。
- 交付物卡片覆盖缺失、草稿、待会签、已会签、已归档。
- 下一步行动覆盖可执行、被锁定、需用户确认、需变更分流。
- 风险提示覆盖信息、警告、阻塞、路线变更。
- 会签按钮覆盖待确认、已确认、退回修改。
- 变更项覆盖当前阶段缺口、增强项、后续阶段、Backlog、拒绝。
- AI 建议块覆盖推荐、原因和需用户确认的取舍。

### 13.3 响应式验收

- 桌面端首屏同时可见当前阶段、下一步和交付物状态。
- 平板端不丢失会签状态和阻塞原因。
- 移动端仍先展示项目状态和下一步，不退化成聊天工具首页。

### 13.4 证据链验收

- 每个核心页面都能回溯到本真源中的页面定义和结构快照。
- 当前设计版本号唯一且可追溯。
- 结构快照覆盖核心页面、关键组件、空状态、错误状态和阻塞状态。

## 14. 不可偏离项

- 若未来恢复当前 `Web / UI` 候选分支，NextStep 必须以项目驾驶舱为中心，聊天只是辅助入口。
- 所有推进动作都必须绑定阶段门禁。
- 未冻结需求，不允许进入产品定义。
- 产品定义未会签，不允许进入产品原型。
- 产品原型未会签，不允许进入产品载体裁决或恢复 UI 设计真源分支。
- `P2.2` 未裁决，不允许把本文升级为正式 UI 设计真源。
- UI 设计真源未确认，不允许进入工程实现。
- 新需求必须进入变更分流，不得直接插入当前闭环。
- 移动端不得把所有信息压缩成单一聊天流。
- 不得把草稿、说明文字或聊天摘要包装成正式真源。

## 15. 验收标准

- 页面清单、页面目标、核心状态和关键交互完整覆盖 P2 核心页面。
- 组件状态表完整覆盖阶段卡、交付物卡、下一步行动、风险提示、会签按钮、变更项和 AI 建议块。
- 响应式要求、空状态、错误状态和阻塞状态表达完整。
- 设计稿链接、截图证据和设计版本号可追溯。
- UI 验收清单可支持后续逐页面、逐组件核验。
- 文档未提前写入技术栈、API、数据库、版本路线、大里程碑、小里程碑或执行任务包。

## 16. 变更入口

- 当前阶段缺口：若发现页面、状态或组件遗漏，先更新 `docs/change-requests/index.md`，再回写本文。
- 设计增强项：进入 Change Request，由用户确认是否影响当前阶段 DoD。
- 外部高保真设计稿补充：通过 Change Request 追加，不得静默替换当前真源。
