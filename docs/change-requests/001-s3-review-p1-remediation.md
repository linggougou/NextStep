## 1. 变更内容

本变更处理以下当前阶段缺口：

- S3 正文不得以自身验收通过替代 007 独立会签。
- 活动计划不得承诺底层跨文件原子提交，只能承诺事务式写入和业务状态逻辑原子性。
- 005 的 `UI / 产品验收` 路线限定需要独立补充契约，以适配 Skill-first 主路线。
- 已会签 P2 技术前置清单被实质扩展为 Skill-first 技术入口，但新增入口遗漏 008，且未经过复会签。

- 类型：当前阶段关键缺口。

- 处理阶段：当前 S3 阶段。
- 是否改变产品主路线：否。
- 是否进入 S4：否。

## 4. 实施决策

- S3 自查通过只代表具备提交会签条件，不自动形成会签事实。
- S4 入口改为 007、008、009 与 S3 正文分别完成用户会签。
- 活动计划统一使用“事务式写入 / 业务状态逻辑原子性”。
- 保持 005 的历史边界。
- P2 技术前置清单保留用户确认形成的已会签状态与日期；其技术正文恢复到 `HEAD` 的原始会签边界。
- 原先写入 P2 技术前置清单的 006、007、S3 依赖、Interaction Source、项目上下文解析和写入一致性内容迁移到独立待会签的 009。
- 由 008 在会签后补充 005 的 P3 / 验收报告路线限定，并作为路线锁新增的 S4 前置门禁。
- 由 009 在会签后补充 P2 技术前置清单的 Skill-first 技术输入，并把 008 纳入 S4 强制输入。

## 6. 迁移与回滚

- 迁移方式：保留 P2 技术前置的会签元数据，将其技术正文恢复到 `HEAD` 边界；把 Skill-first 增量迁移到 009。
- 迁移证据：`git diff -- docs/architecture/p2-technical-prep.md` 只能保留状态与会签日期差异，不能保留 006、007、008、009、S3 或 Interaction Source 技术增量。
