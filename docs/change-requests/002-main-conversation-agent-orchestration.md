# 主对话 Agent 编排与上下文隔离

状态：已完成，四份材料会签通过
记录日期：2026-07-12
来源：用户在当前会话补充的目标使用场景
所属阶段：S3 Skill 交互真源

## 1. 原始需求

用户在 Codex 打开一个主对话并调用 NextStep。主对话中的 Agent 持续引导用户把 idea 推进为可交付项目；开发、评估、测试等执行任务由主对话 Agent 分派给其他 Agent。执行过程不得挤占或污染主对话上下文。

## 2. 分流结论

- 类型：已完成的 S3 阶段关键缺口；设计、迁移、独立复审和四份正式材料会签均已通过。
- 原因：该需求直接定义主交互载体、主 Agent 职责、执行 Agent 边界、结果回传协议和上下文隔离要求；不补齐将无法准确会签 S3 交互真源。
- 是否影响当前阶段 DoD：是。
- 是否影响阶段出口：是；007、008、S3 正文与 009 已依次会签，原阶段出口已满足。

## 4. 已完成澄清的边界

- 主对话 Agent 是否只负责引导和编排，还是允许直接执行轻量真源维护。
- 哪些任务必须分派给执行 Agent。
- 执行 Agent 能读取哪些项目真源和上下文。
- 执行结果以何种最小结构回传主对话，如何避免完整日志和推理污染上下文。
- 执行失败、超时、冲突、重试和人工确认如何处理。
- 主对话关闭、压缩或恢复后，编排状态如何从文档真源重建。

## 5. 已确认边界

- 主对话 Agent 严格只负责与用户沟通和分派任务。
- 主对话 Agent 不读取或修改项目文件，不开发、不测试、不评估，也不直接回写真源。
- 项目分析、文档修改、代码开发、测试、评估、审查、验证和真源维护都必须在隔离的其他 Agent 任务中完成。
- 其他 Agent 的完整对话、执行过程、日志、代码细节和推理不得进入主对话。
- 主对话只接收面向决策的最小结构化摘要，并向用户呈现需要确认的结论、风险和下一步。
- 该隔离同时服务两个目标：避免无关上下文影响主 Agent 判断，保护用户连续的心流状态。
- 采用三级协作模型：主对话 Agent、执行 Agent、集成 Agent。
- 执行 Agent 负责开发、文档、测试、评估、审查或其他单一任务产出，不负责最终合入判断。
- 集成 Agent 负责读取执行产出、检查差异、处理冲突并生成包含全部业务/产品真源和受门禁状态的不可变最终内容快照；独立复验后只允许追加经独立白名单校验的 `.codex` 审计锚，并以 CAS 一次提升到该锚定提交。
- 主对话 Agent 不直接接收各执行 Agent 的完整结果；原则上只接收集成 Agent 返回的面向决策摘要。
- 所有会修改文件的执行 Agent 必须使用独立工作区或独立分支，不得直接修改主工作区。
- 测试、评估和审查 Agent 默认只读；若确需产出文件，必须使用隔离工作区并明确产物边界。
- 集成 Agent 是唯一允许生成最终集成快照并提交正式引用提升的角色，但不能形成替代独立复验的验收结论。
- 多个执行 Agent 可以并行，但每个任务包必须声明输入、输出、允许修改范围、禁止修改范围和验收标准；并行任务的文件边界必须互斥。
- 执行 Agent 失败、超时或产出不合格时，其隔离结果可以被废弃，不得污染主项目、其他执行任务或主对话上下文。
- 用户确认阶段目标或执行计划后，主对话 Agent 可以在该边界内自动分派开发、文档、测试、评估、审查和集成任务。
- 计划内普通任务的分派、排队、开始和完成不需要逐次请求用户确认，避免反复打断用户心流。
- 出现路线变化、范围扩大、不可逆操作、安全风险、成本显著增加或验收失败时，主对话 Agent 必须暂停自动推进并请求用户决定。
- 集成完成后，主对话只接收和呈现结果、证据引用、关键风险、待决策项与下一步，不展开执行过程。
- 主对话采用“默认安静、按需展开”的进度呈现方式。
- 默认只显示当前阶段、进行中数量、待集成数量、阻塞数量和下一决策点等紧凑状态。
- 默认不展示 Agent 名称、完整任务列表、执行日志、代码差异、测试输出或内部推理。
- 只有任务阻塞、需要用户决策，或用户主动询问时，主对话才展开对应范围的信息。
- 用户沟通只有一个入口：执行 Agent 和集成 Agent 不得直接向用户提问或要求用户确认。
- Agent 能在已确认计划内自行解决的问题应自行处理；缺少输入但不影响路线时，返回结构化阻塞摘要。
- 涉及产品取舍、范围变化、路线、不可逆动作、安全或显著成本时，Agent 必须停止对应任务并上报主对话 Agent。
- 只有主对话 Agent 可以向用户提问和接收用户决定。
- 用户决定不得连同整段对话直接转发；主对话 Agent 必须将其重新包装为最小、明确、可验收的任务上下文后再分派。
- 主对话恢复采用“项目真源 + 最小会话检查点”，不默认加载完整旧聊天。
- 每次用户作出关键决定后，主对话 Agent 必须分派持久化任务；集成 Agent 写入对应真源并返回持久化确认和版本标识。
- 最小会话检查点只记录项目、当前阶段、已确认决策、用户稳定偏好、活动任务 ID 与状态、尚未持久化的决定、当前阻塞、下一决策点和真源基线标识。
- 新主对话启动时，由只读上下文恢复 Agent 对照检查点、路线锁、当前计划、正式真源和最近验证记录重建状态。
- 检查点与项目真源一致时，只返回精简恢复摘要；不一致时只把冲突项带回主对话，不展开无关历史。
- 完整旧聊天仅在检查点与真源冲突且现有证据无法裁决时作为最后证据按需读取，不自动加载。
- 所有任务必须使用唯一任务 ID；消息处理和集成操作必须支持幂等，重复、延迟或乱序消息不得造成重复修改、重复派发或状态倒退。
- 主对话未收到集成 Agent 的持久化确认前，不得把用户决定视为已经正式生效；中断恢复时必须把它标记为“尚未持久化”。
- 所有执行 Agent、测试 Agent、评估 Agent、审查 Agent、恢复 Agent 和集成 Agent 都不得继承完整主对话。
- 子 Agent 只能接收完成当前任务所必需的最小结构化任务包。
- 最小任务包至少包含：任务 ID、控制代际、任务尝试、派发控制消息 ID、任务包摘要、项目根、基线版本、当前目标、必要的已确认决策、允许修改范围、禁止修改范围、输入真源、输出要求、验收标准、失败与上报规则。
- 用户偏好、历史讨论、其他任务信息和与当前任务无关的项目上下文默认不传递。
- 子 Agent 发现信息不足时，只能返回结构化信息缺口，不得自行读取或请求完整主对话。
- 集成 Agent 同样只接收待集成任务、对应产出、相关真源和验收边界，不获取完整聊天历史。
- 集成 Agent 同时承担执行前的任务准备和执行后的结果集成，不新增长期的第四类角色。
- 执行前，主对话 Agent 只把用户目标和必要决定交给集成 Agent；集成 Agent 读取路线锁、当前计划和相关真源，生成执行计划与最小任务包。
- 主对话 Agent 只向用户展示集成 Agent 返回的计划摘要和必要决策；用户确认后，主对话 Agent 按已生成任务包自动分派执行 Agent。
- 执行完成后，由集成 Agent 在隔离暂存区检查产出、处理冲突，并把业务/产品真源、会签/阶段状态、项目内任务状态、检查点和复验前验证留痕写入不可变最终内容快照；独立复验产生凭证后，仅生成写入最终结论与凭证摘要的 `.codex` 审计锚，并由独立验证器确认路径白名单和业务/真源子树不变；最后以 compare-and-swap 或等价原子引用移动一次提升到锚定提交，提升后不得补写项目内容。
- 主对话 Agent 不校验任务包内部文件细节，也不直接审阅执行差异；这些责任属于集成 Agent。
- 执行、集成和验收职责必须相互独立，集成 Agent 不得单独批准自己的集成结果。
- 开发或文档产出必须由独立测试 Agent 或验证 Agent 检查；涉及产品与交互要求时，必须由独立评估 Agent 验收。
- 高风险任务、阶段出口或发布判断必须追加独立审查 Agent。
- 测试、验证、评估和审查 Agent 默认只读，只返回结构化结论与证据引用。
- 只有当前任务所要求的独立验证全部通过后，集成 Agent 才能更新正式状态或形成可提交会签的结果。
- 任一独立验证失败都不得包装为完成；必须向主对话上报，由用户决定修复、延期或调整范围。

## 6. Codex 适配裁决

- 采用 `三层职责 + 扁平调度 + 独立任务隔离 + 项目真源通信`。
- 三层是主对话 Agent、集成 Agent、执行 Agent 的逻辑职责，不要求物理上的三级递归 Agent。
- 主对话 Agent 根据集成任务生成的最小任务包，扁平创建和调度独立 Codex task。
- 修改型任务使用独立 worktree；测试、评估和审查任务默认只读。
- Codex 提供任务与工作区运行能力；NextStep 提供任务包、结果信封、状态机、恢复和主对话读取规则。
- 同一任务内普通 subagent 不作为满足严格主对话隔离的正式执行通道。
- 当前详细交互协议真源：`docs/design-docs/s3-skill-interaction-source.md`。
- 历史设计来源与复审证据：`docs/design-docs/s3-main-conversation-agent-orchestration-design.md`；该文件已迁移，不再作为当前协议真源。

## 9. 运行时风险与控制

| 风险 | 影响 | 控制与失败结论 |
|---|---|---|
| 依赖满足但主对话无法获知 | 后续验证任务永远不创建，项目停滞 | 集成控制面生成持久化 `dispatch-ready`；主对话返回 `dispatch-ack`；超时重发使用同一去重键 |
| 重复、延迟或乱序控制消息 | 重复创建任务或状态倒退 | 控制消息 ID、任务包摘要、基线和去重键联合校验；重复信封返回原确认 |
| 旧基线信封晚于新基线到达 | 不同去重键使过期任务被误派发 | 使用单调 `plan_generation` / `task_attempt` 和不可变 `generation-advance` 墓碑；主对话持久化最高代际并确定性拒绝低代际信封 |
| 已启动旧任务返回迟到结果 | 已撤销产出或验收结论被集成 | 所有结果和验收信封携带控制代际与任务包摘要；集成控制面先合并最高代际，低代际结果标记 `stale-result` 且禁止驱动依赖或集成 |
| 集成冲突改变已验证候选 | 未验证内容进入正式状态 | 生成不可变最终集成快照，对精确摘要独立复验；任何内容或基线变化使旧结论失效 |
| 提升后补写正式状态 | 项目正式内容不再等于独立复验摘要 | 业务/产品真源和受门禁状态预先进入最终内容快照；最终结论只通过经独立验证的 `.codex` 审计锚追加；提升后禁止任何项目写入 |
| 最终复验只留在项目外 | 不满足项目根 `.codex` 验证与审查留痕 | 从已复验内容快照生成仅修改 `.codex` 白名单的审计锚，独立校验路径与凭证绑定后 CAS 一次提升 |
| 凭证、审计锚或 CAS 能力不可用 | 最终证据无法绑定或并发提升可能覆盖新基线 | 纳入 `project-probe`；可由用户显式执行且证据可校验时进入 `manual-isolated`，否则 `blocked` |
| Codex 宿主组合能力不可用 | 无法保证独立任务、只读验证、候选起点或自动归档 | 每个计划和恢复周期执行两阶段 capability preflight；只能进入 `full`、`manual-isolated` 或 `blocked` |
| 预检循环依赖 | 尚未证明可创建任务，却要求集成任务执行预检 | 主对话先执行无项目读写的 `host-bootstrap`；通过后才创建一次性 `project-probe` |
| 任务已创建但确认未持久化 | 恢复重试可能创建重复后台任务 | `full` 必须具备宿主幂等键或可查询任务标记和单写者台账；否则只允许 `manual-isolated` |
| 只靠 Agent 角色提示词声明只读 | 验证任务可能修改被测对象 | 使用宿主只读约束，或一次性隔离副本并丢弃写入；两者都不可用则阻塞 |
| 主对话恢复时控制确认丢失 | 重复派发或遗漏任务 | 恢复任务核对控制消息台账、去重键和宿主任务 ID，补发原确认或拒绝过期信封 |
| 自动归档能力不可用 | 任务列表产生噪声 | 保留已完成任务并标记待人工归档；不影响正式产物正确性 |
| 人工降级被误认为严格隔离 | 用户认为上下文仍受保护，实际已退化 | 仅允许保持独立任务的 `manual-isolated`；串行同任务执行必须重新分流并由用户确认，不沿用本设计验收 |

## 10. 验证成本

| 验证项 | 最低成本 | 触发频率 |
|---|---|---|
| capability preflight | 先做无项目读写 `host-bootstrap`，再用一次性隔离 `project-probe` 探测 worktree 起点、候选物化、验证隔离、控制信封、恢复和归档 | 新宿主、新项目、能力版本变化、恢复时或预检过期时 |
| 控制面契约测试 | 覆盖正常确认、重复、超时、乱序、过期、代际提升、墓碑先后顺序、计划变化和恢复重放 | 控制协议变更时必测，发布前回归 |
| 结果代际回归 | 覆盖旧执行结果、旧候选验证、旧审查、同代际身份冲突和恢复后结果重放 | 控制协议变更时必测，发布前回归 |
| 候选验证 | 对不可变候选提交或快照执行任务要求的测试、评估和审查 | 每个修改型任务 |
| 最终集成独立复验 | 对包含全部项目内正式状态的精确摘要执行整体验证，生成项目外不可变凭证，并验证提升事务只移动引用 | 每次正式提升前；最终内容或基线变化后必须重跑 |
| 审计锚验证 | 校验只修改允许 `.codex` 路径、字段匹配复验凭证、父提交和业务/真源子树摘要不变 | 每个最终复验凭证 |
| 恢复演练 | 验证未确认信封不会重复派发，过期信封不会继续执行 | 状态机或持久化格式变更时 |
| 人工隔离模式验证 | 检查用户显式创建的任务 ID、环境和候选摘要仍可绑定 | 每次进入 `manual-isolated` 模式 |

这些验证增加后台任务和等待时间，但属于严格上下文隔离及正式状态正确性的必要成本，不得用主对话自行检查或集成 Agent 自我批准替代。

## 11. 迁移与回滚

迁移顺序：

回滚规则：

- 书面设计复审失败：保留审查包和本 CR，状态退回“待修订”，不触碰四份正式材料。
- 迁移中断或部分写入：只回退本次可识别的迁移差异，原四份材料保持待会签，原 S4 门禁继续关闭。
- 宿主预检为 `manual-isolated`：保留设计语义，改由用户显式创建独立任务或传递最小控制信封，并记录人工确认。
- 宿主预检为 `blocked`：停止当前执行链，保留任务、控制消息和候选快照，不把任何候选提升为正式状态。
- 项目外凭证、审计锚或正式引用 CAS 预检失败：能由用户显式完成并提供可独立校验证据时进入 `manual-isolated`；否则保持 `blocked`。
- 审计锚验证失败：废弃锚定提交，不改变最终内容快照；修正审计字段后重新生成并验证锚。
- 正式 CAS 失败：保持 `待正式提升`，不发送成功摘要、不归档；若基线变化，废弃凭证和锚并重新生成最终内容快照。
- 用户不接受人工隔离或宿主长期不满足强制能力：通过新的 Change Request 重新裁决载体或隔离等级，不得在本 CR 内静默改为同任务执行。
- 已迁移但尚未会签：可以按本 CR 的迁移清单回退增量；不得改写既有会签历史。
- 已会签后再要求改变本协议：必须新建 Change Request，评估是否需要四份材料重新会签。

## 12. 宿主能力不可用时的决策

- 自动任务创建、控制信封投递或自动归档不可用，但独立任务、不可变候选和最终独立复验仍可通过用户显式操作保证：进入 `manual-isolated`，只上报最小操作请求。
- 独立任务不可用、候选不能物化、验证无法隔离、最终复验无法绑定精确摘要或任务身份无法去重：进入 `blocked`。
- `blocked` 不等于实现失败，也不能包装成严格隔离已满足；主对话只向用户说明缺失能力、影响和可选路线。
