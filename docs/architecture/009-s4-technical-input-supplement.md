## 4. 补充核心对象

S4 至少需要评估以下新增或重定义对象：

| 对象 | 作用 | 技术关注点 |
|---|---|---|
| Interaction Source | 当前分支交互真源 | 版本、会签状态、引用关系、验收映射 |
| Project Context | 唯一项目上下文 | 规范化绝对项目根、同名消歧、符号链接、权限与越界 |
| Candidate Change | 用户确认前的候选变更 | 基线标识、目标文件、影响摘要、过期与冲突检测 |
| Write Transaction | 一次正式真源回写 | 业务状态逻辑原子性、部分写入、验证和安全回滚 |
| Acceptance Profile | 当前路线验收配置 | 交互验收、产品验收和条件性 UI 还原验收 |
| Capability Preflight | 当前宿主、版本、项目与权限组合的能力证据 | `host-bootstrap` / `project-probe` 两阶段、检测时间、有效期与三态结论 |
| Task Registry | 隔离任务、依赖、控制代际和状态的项目台账 | 单写者、不可变任务包引用、幂等恢复、普通通知不得驱动依赖 |
| Control Envelope | 主对话与集成控制面的最小机器消息 | 版本、控制消息身份、代际、任务包摘要、去重、确认、过期与撤销；详细字段以 S3 正文为准 |
| Generation Snapshot | 恢复时的最高有效代际与未确认墓碑摘要 | 单调合并、乱序拒绝、快照与持久化控制台账一致性 |
| Immutable Candidate | 修改任务物化的不可变候选提交或等价快照 | 精确基线、内容摘要、来源任务身份和只读验证起点 |
| Final Content Snapshot | 已集成且待精确最终复验的不可变项目内容 | 业务/产品真源、受门禁状态、任务台账、检查点与复验前留痕完整性 |
| External Verification Credential | 独立最终复验产生的项目外不可变凭证 | 控制身份、复验运行、内容摘要、预期基线、验证任务身份、结论与证据绑定 |
| Audit Anchor | 从已复验内容快照追加的项目根审计锚 | 仅允许 `.codex` 白名单、凭证字段一致、父快照与业务/真源子树不变 |
| Formal Reference CAS | 将正式引用一次提升到已验证审计锚的事务 | 预期基线、快进或等价原子移动、竞争失败保持待提升、可恢复重试 |

`UI Design Source` 仅在恢复含 UI 分支时作为追加对象，不是当前 Skill-first 路线的默认 S4 输入。

## 5. 补充系统能力

S4 技术方案必须覆盖：

- 能力预检：每次建立或恢复执行计划时，先执行不读写项目文件的 `host-bootstrap`；只有证明独立任务可创建与查询后，才创建一次性隔离 `project-probe` 验证项目级 worktree 起点、候选物化、验证隔离、控制信封往返、恢复、项目外凭证、审计锚、正式引用 CAS 和归档。
- 预检三态：结论只能是 `full`、`manual-isolated`、`blocked`。`full` 必须消除或可恢复“任务已创建但确认未持久化”窗口；`manual-isolated` 只允许用户显式创建独立任务或传递最小控制信封，仍保持上下文和文件隔离；无法保证独立任务、不可变候选、最终复验或身份绑定时为 `blocked`。
- 禁止静默降级：同一任务串行执行不能冒充严格隔离；只有用户明确接受降低隔离等级并重新进入变更分流后，才能作为另一方案处理。
- 项目上下文解析：将用户确认的项目标识解析到唯一规范化绝对项目根。
- 读写边界控制：所有正式读写限制在已确认项目根内，越界或无权限时阻塞。
- 扁平调度与职责隔离：主对话只沟通、决策和调度，不读取项目文件；集成控制面根据任务注册表生成控制信封；执行、验证、评估和审查在独立任务中完成。
- 控制身份与恢复：任务包、控制信封、结果、验证和审查结论必须绑定控制消息、计划代际、任务尝试和内容摘要；恢复先合并代际快照与撤销墓碑，再重放有效消息。
- 候选变更管理：正式写入前展示目标文件、影响范围、会签后果和基线证据。
- 冲突检测：确认后目标文件发生变化时重新读取和重新确认，不覆盖用户新改动。
- 事务式写入：不承诺底层跨文件原子提交，但任一写入或验证失败时业务状态不得生效。
- 部分写入恢复：只回退本轮可安全识别的修改；无法安全回退时阻塞并保留证据。
- 阶段状态提交：只有全部写入和验证成功后，才能更新会签或阶段状态。
- 精确最终复验：最终内容快照必须不可变并包含全部项目内正式状态；独立复验生成项目外不可变凭证，任何内容、身份或基线变化都使旧结论失效。
- 审计锚与正式提升：独立校验审计锚只修改允许的项目根 `.codex` 路径且绑定凭证；正式引用仅以 CAS、快进或等价原子移动一次提升，失败时不误报成功、不归档。
- 归档隔离：归档是正式提升后的项目外副作用；失败时保留待人工归档，不得回写或改变正式内容结论。
- 验收配置：所有路线执行交互验收和产品验收，含 UI 分支追加 UI 还原验收。

## 6. S4 必答问题

- 项目根如何发现、规范化、确认和持久化引用。
- 工作区包含多个项目、同名项目或符号链接时如何消歧。
- 候选变更使用什么基线标识，如何检测确认后的并发修改。
- 多文件写入如何组织事务、验证、补偿和人工恢复。
- 如何证明会签状态不会在部分写入或验证失败后提前生效。
- Interaction Source 如何关联产品真源、技术方案、里程碑和验收报告。
- Acceptance Profile 如何按路线启用或禁用 UI 还原验收。
- `host-bootstrap` 如何在不读写项目的前提下发现宿主能力，能力证据如何绑定宿主标识、版本、检测时间和有效期。
- `project-probe` 如何在一次性隔离环境中验证 worktree 精确起点、候选物化、只读验证、控制往返、恢复、凭证、审计锚、CAS 与归档，且只返回预检结果信封。
- `full`、`manual-isolated`、`blocked` 如何判定；哪些能力缺失必须阻塞，哪些仅允许用户显式操作。
- 如何证明任务创建幂等、`dispatch-ready` / `dispatch-ack` 确认可恢复，且乱序代际和迟到结果不会驱动状态倒退。
- 任务注册表、代际快照、不可变候选和最终内容快照分别存储什么最小状态，如何避免主对话读取项目内容。
- 项目外复验凭证如何保持不可变并绑定验证任务身份、控制代际、最终内容摘要和预期正式基线。
- 项目根审计锚如何限制写入白名单、验证父快照和业务/真源子树不变，并与项目外凭证逐项对应。
- 正式引用 CAS 如何检测并发竞争、保持 `待正式提升`、区分安全重试与必须废弃旧凭证重做的基线变化。
- 日志与证据如何避免泄露不应记录的敏感内容。

## 7. 风险与验证要求

| 风险 | 失败表现 | S4 必须给出的验证方式 |
|---|---|---|
| 写错项目 | 同名或错误工作区导致真源污染 | 多项目、同名、符号链接和越界用例 |
| 覆盖用户改动 | 确认后文件变化仍被覆盖 | 基线变化与冲突重试用例 |
| 部分写入误报成功 | 部分文件失败但阶段已推进 | 故障注入、状态不生效和补偿验证 |
| 验收配置错误 | 非 UI 路线被要求 UI 报告，或 UI 路线漏验 | Skill-only 与含 UI 两类验收矩阵用例 |
| 回滚破坏既有内容 | 恢复动作覆盖非本轮改动 | 变更归属识别和不可安全回退阻塞用例 |
| 预检循环依赖或静默降级 | 尚未证明可创建隔离任务却要求项目任务做预检，或同任务串行冒充严格隔离 | `host-bootstrap` 先行、`project-probe` 后行，以及 `full` / `manual-isolated` / `blocked` 三态转换用例 |
| 控制消息乱序或迟到结果 | 旧代际任务被派发、旧候选或验收结论进入最终状态 | 代际提升、撤销墓碑、确认丢失、恢复快照、`stale-result` 与 `identity-conflict` 回归用例 |
| 验证污染被测对象 | 所谓只读验证修改候选并让结果不可复现 | 宿主只读约束或一次性隔离副本写入检测与丢弃用例 |
| 项目外凭证可变或身份错绑 | 复验结论无法证明针对哪个任务、代际或最终内容 | 凭证不可变性、摘要校验、验证任务身份与预期基线绑定用例 |
| 审计锚越界 | 复验后借审计写入修改产品真源、任务台账或检查点 | 路径白名单、父快照、凭证字段一致和业务/真源子树摘要不变用例 |
| CAS 竞争 | 正式基线变化仍覆盖提升或错误宣告成功 | 并发引用变化、失败保持待提升、安全重试和基线变化后凭证失效用例 |
| 归档失败 | 提升成功后任务噪声残留，或归档失败反向修改项目状态 | 项目外幂等重试与待人工归档用例，验证正式引用和内容摘要不变 |
